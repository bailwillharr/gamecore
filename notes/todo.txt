Replace mutable FrameState with immutable FrameInput, Mutable FrameOutput. Split systems between 'simulation' and 'presentation'.
	Simulation systems cannot modify FrameOutput, they only receive FrameInput as const ref parameter.
	Presentation systems receive FrameInput const ref, but also receive FrameOutput as a mutable ref parameter.
Allow for System onUpdate()'s to be run in parallel if they don't modify the same thing, or depend on each other.



Pipeline variants (done: see MaterialFeatures and RenderBackend::setWorldShaders()):
	A variant is still given a (fallback) texture for the slots it doesn't sample, as every variant uses the same descriptor set layout.
	Draws aren't sorted by pipeline, so the pipeline can be rebound more often than needed.
	A variant is compiled the first time it is drawn, which can cause a hitch.

Blend modes (see MaterialBlendMode):
	Alpha blended draws are sorted by the distance of their entity's origin, not per triangle, and don't write depth. Big or
	intersecting see-through meshes can be drawn in the wrong order.
	Alpha tested edges are hard: no alpha to coverage.
	Materials are single sided, so cut out leaves can't be seen from behind.

Emission:
	Emissive materials glow but don't light anything, and there is no bloom, so they can't look brighter than white.
	Emission is added after the exposure, so it isn't in physical units like the lights are: 1 is about a lit white surface.

Lights:
	Every fragment loops over every point light in the world (at most WorldDrawData::MAX_POINT_LIGHTS, the rest are dropped).
	Cull lights per object or use clustered shading.
	No spot lights. Only one directional light.

Shadows (see ShadowMapComponent and tools/gcpak_editor/src/shadow_baker.h):
	Only the directional light casts shadows, and only from a shadow map that gcpak_editor baked for a glTF scene. Things that
	move, or that aren't in the prefab, don't cast shadows. Point lights don't cast any.
	One shadow map per world. One shadow map covers the whole prefab, so a big world gets big texels (cascades would fix that).
	Alpha blended materials cast all or nothing shadows (cut at an alpha of 0.5), as there is only one depth per texel.
	The baker reads the nearest texel of the full size texture for alpha tests, so the shadows of fine cut outs are harder
	edged than what is drawn.
	The baker is single threaded and rasterises every triangle on the CPU.
	There is no way to bake the shadows of a prefab that wasn't made from a glTF file.



Collisions (see gc_collision_system.h and tools/collision_test):
	The system only answers queries (ray casts, sphere overlaps, box queries). There is no collider against collider test, and
	nothing is moved: no physics.
	A collider is always a triangle mesh. Simple shapes (boxes, spheres, capsules) would be cheaper for things that move.
	No swept queries, so something fast and small can pass through a thin wall between two frames.
	The broad phase tree is never rebalanced. Adding a whole world's colliders one at a time gives a deeper tree than building it
	in one go would.
	Each mesh's triangles are copied and sorted into a tree the first time a collider uses it, on the main thread.
	Queries see the world as of the CollisionSystem's last update.
	gamecore_template doesn't use it yet.

Use the same ByteReader and ByteWriter classes engine-wide.
	No more NetByteReader for network stuff, and also stream usage for file stuff.
	Just standardise the serialised format used both for file and network.



Prefabs (see gc_prefab.h, gcpak_prefab.h and tools/prefab_test):
	Components are found by their NAME when a prefab is loaded, but every World still has to register its components in the same
	order because getComponentIndex<T>() is global. A World should map component types to its own indices instead.
	A prefab can't refer to another prefab (nested prefabs). A game component can store a prefab's Name and load it itself.
	Components can't refer to other entities in the prefab, as Entity handles can't be serialised. Would need the loader to
	translate prefab entity indices into Entity handles.
	There is no version number in a serialised component. If its size changes, old prefabs are rejected.
	gcpak_editor can't view or edit prefabs yet.
	Most of gamecore_template's components aren't serialisable yet (only SpinComponent is).



Use 64 bit hash for gc::Name (4 billion combinations isn't that much, and I don't see a reason why Names can't be 8 bytes instead of 4)



gc::World needs some serious optimisation:
	forEach<> currently iterates through the entire m_entity_signatures array, and then calls getComponent<> for every component for
	every matching entity. getComponent<> also checks m_entity_signatures, so I should probably make a faster getComponentUnchecked<>.

	Add a World::getTransform() that doesn't check, since TransformComponents always exist (unless the entity doesn't exist!)
	But if the entity doesn't exist when calling getComponent<>, that should be UB anyway.
	
	The comment in findEntity() suggests that a Name->Entity map should just be made for optimisation purposes.
	But the the same name is allowed for different entities under different parents, so this won't work.
	Alternately, use TransformSystem::getChildren().

	m_component_names can probably be merged with m_component_arrays, likewise for m_system_names, which can be merged with m_systems.



Networking:
	Packets are authenticated by a secret session token but are not encrypted or signed, so an attacker that can read the
	traffic between a client and the server can hijack or close the session. Fixing this needs a crypto library (e.g. monocypher
	for a key exchange + AEAD).
	Handle a client's address changing mid-session (NAT rebind). Currently packets from the new address are ignored and the
	session times out.
	Any host can make the other one quit by sending a "shutdown" event (see App::run()). That's handy for testing but shouldn't
	stay in the engine.


Replication (see replication.txt):
	The server believes whatever a client says about the transform of the entities it owns. Check it (speed, bounds).
	Client side prediction, for games where the server should move the players.
	Lag compensation for hit detection.
	Interest management, so that clients are only sent the entities near them.
	Replicated entities can't be children of other replicated entities.
	Serialising every replicated component every tick to detect changes is simple but won't scale to thousands of entities.



Asset compilation (see tools/gcpak_editor/README):
	gcpak_editor decides whether an image file is an sRGB or a linear texture from its file name. There's no way to override it.
	glTF's constant factors are baked into textures by gcpak_editor when there is a texture (a material's constants replace a
	texture, they don't scale it), and double sided materials are dropped.
	Mesh assets have 16 bit indices, so gcpak_editor splits big glTF meshes into several. Support 32 bit indices instead.
	gcpak_editor compiles on the main thread, so the window freezes while a big folder is added.
	Nothing recompiles assets when their source files change. The build could run gcpak_editor --pack.
	No animations or skins.
